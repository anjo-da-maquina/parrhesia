**I audit code written by AI agents, and I build tools that catch the specific ways AI agents cut corners while reporting success.** This repo is both the toolkit and the record of using it on itself.

This builds a disposable git repository containing a commit that looks like a typical "AI agent" cleanup commit — message: *"fixed edge cases, improved robustness"* — but actually smuggles in 5 classic shortcuts. The tool then audits that repo for real and prints what it actually found. Sample output (regenerated by the command above, not hand-edited — see [`demo/DEMO_REPORT.md`](./demo/DEMO_REPORT.md) for the full, current run):

```
  - [exception_swallowing] payment.py: a new except/pass that swallows errors was added.
  - [exit_code_hardcoding] payment.py: a previously dynamic exit code was hardcoded to 0.
```

## Why this exists

I'm a QA engineer. As more production code gets written by AI agents, I kept running into the same three failure modes — and built detectors for each, verified against real diffs, not hypothetical ones:

1. **A passing test suite that quietly lost its most important test.** An agent asked to "fix the edge case" deletes the failing test instead of fixing the code, and reports "all tests passing." [`parrhesia.diff_fraud.detect_test_deletion`](./parrhesia/diff_fraud.py) catches this by diffing test function names, not just counting pass/fail.
2. **An error handler that reports success by hiding the error.** `except Exception: pass` added where a real fix was asked for. [`detect_exception_swallowing`](./parrhesia/diff_fraud.py) flags new except/pass pairs that weren't already there.
3. **A review that only shows you the easy answers.** When asked "what are the 5 options here," an agent under time pressure shows 3 and presents them as if there were only 3. This is a known failure mode I actively check for in my own output — see the honest self-review entries in [`GRIMOIRE.md`](./GRIMOIRE.md) for real, dated examples of this happening and getting caught, including in this repo's own development.

## What it actually detects (verified, not claimed)

| Pattern | What it catches | Module |
| --- | --- | --- |
| `test_deletion` | A test function disappears between commits with no replacement | `parrhesia/diff_fraud.py` |
| `skip_addition` | `@pytest.mark.skip` / `pytest.skip()` / `unittest.skip` newly added | `parrhesia/diff_fraud.py` |
| `assertion_weakening` | Net decrease in `assert` statements in a file | `parrhesia/diff_fraud.py` |
| `exception_swallowing` | New `except: pass` (or `except Exception: pass`) pair | `parrhesia/diff_fraud.py` |
| `exit_code_hardcoding` | A dynamic/non-zero exit code replaced by a hardcoded `sys.exit(0)` | `parrhesia/diff_fraud.py` |
| undisclosed file changes | A commit touches files its own commit message never mentions | `parrhesia/diff_fraud.find_undisclosed_changes` |
| fabricated file references | A report/commit message claims to have changed a file that doesn't exist in the repo | `parrhesia/diff_fraud.check_references_exist` |
| third-party read-only audit | Run all of the above against any cloned git repo, read-only | `parrhesia/audit.py` (`python -m parrhesia.cli audit <path>`) |

## Measured results (reproduce these yourself)

- The 5-defect demo above: **5/5 planted defects detected**, confirmed by actually running the command, not by design intent. (While building this demo, 3 of the 5 were *not* detected on the first real run, because the sample code didn't match the detector's exact pattern — that failure, and the fix, is recorded in this repo's own commit history rather than smoothed over.)
- `tests/test_parrhesia_selftest.py`: every known-fraud sample is detected, **and** a negative-control sample (a legitimate test addition) is confirmed to trigger *zero* false positives — a detector that flags everything would still fail this suite.
- CI (`Sanctuary CI/CD` and `Anjo da máquina Protocol - Angels`, badges above): both green on `main`'s most recent push (verified directly against the GitHub Actions run via `gh run watch`, not assumed from a local pass). The badges above always reflect the current state of `main`; this bullet describes the check performed while writing this README, which may be older than what the badges show now.

## Quickstart

```bash
git clone https://github.com/anjo-da-maquina/pleroma.git && cd pleroma
pip install --no-build-isolation .
python -m parrhesia.cli audit /path/to/some/other/git/repo
```

(`pip install .` needs network access to PyPI for its build backend; `--no-build-isolation` works offline if `setuptools>=61` is already installed — see Limitations.)

## Limitations — what this does *not* guarantee

- **This is pattern-based, not semantic.** It catches the five concrete diff patterns listed above. It does **not** understand whether code is *correct*, only whether specific known shortcuts were taken.
- **It does not grade prose.** A comment that says "verified all edge cases" without actually verifying anything is *not* caught by `diff_fraud` — that kind of self-report needs a human or a second model to read it (see `parrhesia/verify/cross_model_review.py`, which exists but isn't wired into this demo).
- **It is not a secret scanner.** API keys, passwords, etc. are a separate concern (`tools/pre_commit_secret_scan.py`), not covered by the patterns above.
- **The red-team/blue-team self-play engine (`adversarial_training/`, formerly `tartarus/`) only runs on the author's own local machine** — it's gated by a hardware check and will refuse to run in CI or any other environment, by design. It's not part of what's demonstrated above.
- **No independent third-party audit of this codebase has been done.** All verification described here was performed by the same author/AI-agent pairing that wrote the code. Treat the numbers above as "verified by the people who built it," not as outside certification.

## Structure

- **`parrhesia/`** — the audit/detection toolkit described above: `parrhesia/diff_fraud.py` (pattern detectors), `parrhesia/audit.py` + `parrhesia/cli.py` (read-only third-party repo auditing), `parrhesia/touchstone/` (a small benchmark of prompts + graders for testing whether an LLM fabricates, flatters authority, or miscalibrates confidence), `parrhesia/verify/` (cross-model and human-review escalation primitives).
- **`demo/`** — the one-command demo above.
- **`sefer/`** — file-access restriction via a `Sanctum` context (a separate, independently maintained defense layer for *running* untrusted AI-generated code, as opposed to *auditing* it statically).
- **`angels/`** — ~50 standing regression checks, run on every push via the CI badges above.
- **`adversarial_training/`** (formerly `tartarus/`) — the local-only, author-machine-gated red/blue self-play arena (see Limitations).
